Build troubleshooting encountered and resolved
Visual Studio's build tool could not locate this project in its open solution;
explicit dotnet project builds above succeeded without editing any solution.
Android's linker requires explicit RootMode="All" on TrimmerRootAssembly.
OneDrive marked generated Java class directories ReadOnly and packaging failed
with XARDF7024. Clear ReadOnly only on the affected generated classes directory
and its child directories, then repeat the normal build:
  $classes = '.\PulsePal.Phone.Android\obj\Release\net10.0-android\android\bin\classes'
  Get-ChildItem $classes -Force -Recurse -Directory | ForEach-Object { $_.Attributes = $_.Attributes -band (-bnot [System.IO.FileAttributes]::ReadOnly) }
  $directory = Get-Item $classes -Force
  $directory.Attributes = $directory.Attributes -band (-bnot [System.IO.FileAttributes]::ReadOnly)
The same fix was needed for Debug. No permissions/ACLs or other processes changed.
An attempted alternate IntermediateOutputPath failed because it propagated to
the shared reference; its scratch directory was removed. Do not use that option.

Native support and data
This uses Android 14/API 34+ framework HealthConnectManager, NOT AndroidX's
provider client. On Android 9-13 the app opens but health reads report Unsupported,
even with the separately installed Health Connect provider. Native API 34 types
are isolated behind runtime guards. No background services, workers or sync exist.
Manifest requests INTERNET, READ_HEART_RATE and READ_BLOOD_PRESSURE only.
Packaged manifest has no instrumentation or health write permissions in Release,
disables backup and cleartext, and exposes the protected VIEW_PERMISSION_USAGE /
HEALTH_PERMISSIONS rationale alias plus the older rationale action.

Samsung Health must first export supported measurements into Health Connect with
the user's permission; PulsePal does not access a Samsung wearable directly.
Availability depends on source app, device, region and export support. No stress
is measured, synthesized or inferred. No production/debug sample seeding exists.
Only actual HeartRateRecord samples and native BloodPressureRecord values leave
the adapter. BP's systolic/diastolic are from the same record and converted using
InMillimetersOfMercury, never joined by time or fabricated.
HR's MeasuredAt is the individual original sampletimestamp in UTC, NOT the parent
session's start or upload time. ID is healthconnect:hr:<native ID>:<epoch sec>:<nanos>,
preserving nanosecond identity; DateTimeOffset precision is 100 ns.
BP ID is healthconnect:bp:<native ID>. Version uses native LastModifiedTime UTC
ticks, stable when unchanged. SourceApp is native origin package and SourceDevice
is available manufacturer/model. Shared desktop key remains SourceApp/Metric/RecordId.
There are no shared public-interface changes or synthetic revisions.

Reads are bounded snapshots: HR last 24 hours; BP last seven days, each at most
128 results. Four pages of 64 native parent records are scanned per category.
HR parent history spans 30 days to include crossing sessions; only in-window
samples are emitted. This cap is not exhaustive history or deletion reconciliation.
Newest HR samples within the bounded scan are retained regardless of parent order.
First page is descending; subsequent page tokens carry their own sort direction.
Bridge-invalid metadata, timestamps or values are skipped per record. The shared
0 < value <= 1000 limit is a wire validation rule, not a clinical assessment.
No usable records reports NoData, not zero. Denied permissions never start a
category query. Permissions are checked after reads and again before upload;
revoked categories are removed. Query failures are displayed independently and
omitted from upload, not mislabeled denied/no-data; successful categories can sync.
There is an unavoidable check/send race if the OS permission changes during upload;
already-delivered data cannot be recalled by local cancellation.

User flow, lifecycle and memory
Select categories, grant read permissions, paste fresh desktop pairing JSON in the
text field, Pair, compare the entire request GUID and expiry with the desktop,
approve there, Check desktop approval, then Sync now. No automatic polling/upload.
Pairing uses the real shared PinnedBridgeClient / SocketsHttpHandler and its
mandatory pin, hostname/expiry validation and no-redirect/no-proxy policy.
Managed HTTP is configured; no Android native callback fallback is substituted.
Reflection JSON is explicitly enabled and the shared assembly rooted for linking.
Successful compilation/signature checking does NOT validate TLS/JSON on-device.

Leaving the main activity (OnPause), including permission/policy screens, cancels
work and disposes local pairing. It clears pasted text, pending GUID, results and
category selection. During a permission prompt only category choices survive so
the response can be inspected; credentials never survive. Pair again on return.
Late callbacks check cancellation; a generation guard prevents stale status text.
Disconnect clears local credentials/results regardless of remote reachability;
only confirmed DELETE establishes desktop revocation/clearing. Background exit
never sends DELETE: revoke old sessions on the desktop. Screen capture is blocked.
No preferences, logs or disk cache store credentials/measurements. Record staging
and upload array references are cleared after use/failure. This is logical cleanup,
NOT secure erasure of immutable strings, runtime/network/native buffers, clipboard,
native health-store contents or records already delivered to the desktop.
